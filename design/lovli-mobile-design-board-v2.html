Page 1 · v2 Design Direction
Concept, principles, and what changed — the contract for every screen that follows.

Calm Conversation Studio

Lovli is a private, intelligent layer that helps you reply naturally. Every screen is a stage with one object in the light: the chat you're stuck on, the reply you'll send, the memory you're keeping. Everything else recedes.

Mood

calmprivatewarmtactileintelligentminimalalivemade for Indian chats

Design principles

  • Rule of one. One focal surface per viewport region. Group with spacing, never with extra boxes.
  • Light is hierarchy. Depth comes from surface lightness steps + 1px top highlights + one focused shadow — not from borders. Border opacity: focal full, secondary 60%, tertiary none.
  • The chat is the hero. Screenshots render as polished objects; pasted text reads as conversation context, never as a textarea.
  • Emotional type, utility type. 28px display for moments that carry feeling (Reply hero, onboarding, limit). 22px for utility pages. Uppercase micro-labels survive only as tone labels.
  • Motion is meaning. Every state change moves the way the product thinks: gentle, ease-out, 150–320ms. Nothing bounces, nothing shouts.
  • Trust at the moment of anxiety. Privacy cues live where the fear is: the upload, the memory, the login.

What changed from v1

  • Reply: form-in-a-glass-card → single chat canvas with two modes + fixed CTA.
  • Results: three equal cards → reward arc with a lead reply (scale + order, never scores).
  • Memory: CRM field rows → written journal notes with inline soft labels.
  • Pro: plan-card duo → one aspirational unlock narrative.
  • Type: 22px heroes → 28px; body 14 → 15; eyebrow caps removed.
  • Nav: heavy bordered pill → light floating surface with gliding indicator.
  • Background: flat black → stage with soft radial light.
  • Motion: prose notes → live previews + named tokens + haptics map.

Do / Don't

  • Do use lavender only for selection, focus, tone, and small glows.
  • Do keep the white pill as the single brightest thing on screen.
  • Do let empty space carry the premium feel.
  • Don't stack more than one bordered container per region.
  • Don't use scores, rankings, urgency, or social proof.
  • Don't ship heavy blur on scrolling lists (solid glass surfaces instead).

Page 8 · Build Handoff
Full spec lives in docs/MOBILE_DESIGN_HANDOFF_V2.md — this is the on-board summary.

Build order & rules

1 · Foundation first

  • theme/ tokens from page T1 (colors, type, radius, depth shadows)
  • Core components: Screen shell, CTA, GhostButton, Segmented, Chip, Surface/Float cards, BottomNav, Header, Toast

2 · Money path (R1–R8)

  • Chat canvas with Screenshot/Paste modes + example link
  • Customize sheet (@gorhom/bottom-sheet)
  • Thinking state → Results push → copy/haptics → nudge → limit state

3 · Onboarding + auth (O1–O6), then Memory (M1–M4), Pro + Settings (P1–P3)

Ship static first (animate later)

  • O2 onboarding morph (static composition acceptable for v1)
  • Tab cross-fade (default switch is fine initially)

Must animate in v1

  • Reply card stagger · copy morph + toast + haptic · thinking phases · sheet spring · CTA press · screenshot drop-in

Do not build

  • Notifications, streaks, scores, extra reply actions, pricing, comparison tables, delete-account logic, heavy blur on scroll lists

Open risks

  • Segmented control with 3 long labels at 360px width — test truncation ("Hindi + English")
  • Fixed CTA + keyboard on paste mode — use KeyboardAvoidingView, CTA docks above keyboard
  • Backdrop blur on nav: test perf on low-end Android; fall back to solid rgba surface
